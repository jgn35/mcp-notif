- (decision) Spec created from brief + architecture. Brief fully absorbed (source). Architecture spine + solution design referenced as adopted companions — downstream must read them for AD rules, error tables, stack versions.
- (capability) CAP-1: MCP server exposes a notify tool accepting three string fields (title, short_message, detailed_message) and pushes them as a data-only FCM message to the Android device.
- (capability) CAP-2: MCP server validates input — all three fields required, non-empty, within byte limits (title<=100, short_message<=500, detailed_message<=3500) — and rejects invalid payloads before FCM send.
- (capability) CAP-3: MCP server authenticates every incoming request via static bearer token in Authorization header; rejects with 401 on mismatch.
- (capability) CAP-4: MCP server returns structured typed errors to the LLM caller on FCM push failure, with error types encoding retry vs. skip semantics so the LLM can decide.
- (capability) CAP-5: MCP server runs stateless in a Podman container behind an existing Apache reverse proxy that terminates TLS; no session state, no DB, no notification history.
- (capability) CAP-6: Android app receives FCM data-only messages and displays a system notification using BigTextStyle (title + short_message, full text visible).
- (capability) CAP-7: Android app shows the detailed_message in a detail view when the user taps the notification.
- (capability) CAP-8: Android app owns FCM device token generation and surfaces token rotation to the user via UI (onNewToken + settings/toast); MCP server consumes token from env var.
- (constraint) Self-hosted in Podman container, internet-exposed. Stack: Python 3.12+ async + FastMCP 4.x (server), Kotlin latest stable (Android app).
- (constraint) Monouser, single device. No multi-user, no accounts, no multi-device support in V1.
- (constraint) FCM data-only messages (not data+notification) to guarantee onMessageReceived fires in all app states (foreground and background).
- (constraint) MCP server is stateless — no session state, no DB, no notification history. Aligns with MCP 2026-07-28 stateless protocol.
- (constraint) One-way dependency: LLM -> MCP server -> FCM -> Android app. Android makes no calls back to MCP server. No back-channel in V1.
- (constraint) TLS terminated by existing Apache reverse proxy. MCP server listens on localhost inside container, never handles TLS directly.
- (constraint) FCM HTTP v1 API requires service account credentials (OAuth2). No bare API keys. firebase-admin Python SDK 7.5.0 handles token acquisition.
- (constraint) FCM 4KB total data payload limit. Byte limits on notify fields (title<=100, short_message<=500, detailed_message<=3500) account for this with headroom.
- (constraint) Config via env vars for MCP server (FCM_SERVICE_ACCOUNT_PATH, MCP_AUTH_TOKEN, FCM_DEVICE_TOKEN). google-services.json for Android. FCM device token configured manually in V1.
- (constraint) Hexagonal architecture (ports & adapters) for MCP server. notify tool logic is application core; MCP Streamable HTTP is inbound adapter; FCM sender is outbound adapter.
- (note) Non-goals: No notification actions (mark done, snooze, reply to LLM). No notification history. No multi-user/multi-device/accounts. No automated device registration flow. No retry/dead-letter queue in MCP server (LLM owns retry). No rate limiting, mTLS, or OAuth2 server. No log aggregation. No health-check endpoint.
- (assumption) Static bearer token auth is sufficient for V1 monouser internet-exposed server. No mTLS, no OAuth2 server, no rate limiting in V1.
- (assumption) FCM device token configured manually via env var in V1. No automated device registration flow. Manual reconfiguration is the staleness remediation path.
- (assumption) No retry/dead-letter queue in V1. FCM is generally reliable; LLM handles retry logic based on error type.
- (assumption) Android minimum API version deferred to Android build — not specified in brief or architecture.
- (assumption) Android app internal architecture (Activity structure, detail view implementation, lifecycle) deferred to the Android build — not specified in architecture.
