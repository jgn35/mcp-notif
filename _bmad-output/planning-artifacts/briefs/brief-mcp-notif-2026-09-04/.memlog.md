- (decision) Projet perso monoutilisateur: app Android + serveur MCP de notification pousse par le LLM via Firebase
- (decision) Architecture: LLM (avec scheduler integre) appelle le tool notify du serveur MCP -> Firebase -> Android. 3 champs: titre, message court (dans la notif), message detaille (au clic)
- (decision) Deploiement: autoheberge, conteneur Podman. Connecteurs todo MCP deja existants
- (decision) Differentiation: le LLM est le moteur, pas une brique connexe. Les reminder apps concurrentes ne se connectent pas gratuitement a un LLM
- (decision) V1: lecture seule de la notification. Pas d'action (marquer fait, snooze, repondre au LLM)
- (decision) Vision: infra de notification generale, n'importe quel LLM pousse n'importe quel message. Todo = premier use case. Resume d'actualite quotidien = idee future, pas now
- (decision) Scheduler LLM tourne dans le service cloud du LLM. Serveur MCP expose a internet (pas localhost). Auth a prevoir
- (decision) Firebase/FCM: a monter from scratch, fait partie du projet
- (decision) Stack: serveur MCP en Python async avec FastMCP, app Android en Kotlin
- (decision) V1: aucun historique des notifications conserve. Lecture transient uniquement
